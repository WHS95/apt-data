# 한지 (韓地) — 신혼부부 첫 집 데이터

> 국토교통부 실거래가공개시스템 데이터를 신혼부부 의사결정 흐름으로 재구성한 Next.js + PostgreSQL 서비스.

```
호가는 잊고, 실거래로 첫 집을 본다.
```

## 🧭 다섯 개의 뷰 (의사결정 순서대로)

| # | 뷰 | 답하는 질문 | 핵심 지표 |
|---|---|---|---|

| 04 | 권역 비교 | **가성비**는 어디가 좋나? | 평균가·전세가율 종합 점수 |
| 05 | 분양·입주권 캘린더 | **다가오는 기회**는? | 일자별 분양권 거래 |

## 🚀 시작하기

### 1. 의존성 설치
```bash
npm install
```

### 2. PostgreSQL 준비
로컬 / Neon / Supabase 등 무엇이든. 연결 문자열을 `.env` 에 적습니다.
```bash
cp .env.example .env
# DATABASE_URL=postgres://user:pass@host/db 입력
```

### 3. 스키마 생성
```bash
npm run db:generate   # drizzle/<timestamp>_*.sql 생성
npm run db:migrate    # 적용
```

### 4. 시드 데이터 적재 (개발용 더미)
```bash
npm run db:seed       # 시도 17 + 주요 시군구 + 더미 실거래 ~1,600건
```

### 5. 개발 서버
```bash
npm run dev
# → http://localhost:3000
```

## 🧲 실데이터 수집

CLAUDE.md 명세 그대로 TypeScript로 포팅됨.

```bash
# 전체 (2006년 ~ 오늘, 매우 오래 걸림)
npm run 수집:전체

# 증분 (DB 최신 계약일 다음날부터)
npm run 수집:증분
```

`수집_실행.ts` 가 `molit_client` 를 통해 세션 초기화 → 시도 17개 × 물건 8개 × 거래 2개를 1년 단위 분할로 수집 → CP949 CSV 디코딩 → 파싱 → `실거래_저장소` 로 저장합니다.

**증분 수집 키**: `시도_코드 × 물건_유형 × 거래_유형` 단위로 마지막 계약일을 DB에서 직접 조회하므로 별도 상태 파일이 필요 없습니다.

## 🛰 API

| 메소드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/전세가율?시도=11000&물건=A&시작=&종료=` | 히트맵 셀 목록 |
| GET | `/api/예산매물?예산=60000&물건=A&시작=&종료=&초과율=0.05` | 시도별 매물 분포 |
| GET | `/api/단지추이?단지=래미안&시작=&종료=` | 월별 매매·전세 중위 |
| POST | `/api/권역비교` (body: `{ 시군구_코드_목록, 면적_최소, 면적_최대, 시작, 종료 }`) | 가성비 점수 |
| GET | `/api/분양캘린더?시작=&종료=&시도=` | 분양·입주권 일자별 |

## ⚠️ 데이터 주의

1. **인코딩**: 국토부 CSV는 CP949 — `iconv-lite` 로 변환 후 적재
2. **계약일 기준**: 신고일이 아닌 계약일 — 직전 30일 데이터는 누락 가능
3. **정정·해제**: 신고 후 정정/해제 발생 시 수치 변동 — 같은 키에 대해 증분 수집 시 `onConflictDoNothing` 로 안전 처리(중복 방지 인덱스: 시군구+단지명+계약일+면적+층+금액+보증금+거래유형)
4. **공식 통계 아님**: 외부 공개 시 공식 통계 활용 권고
